Update 16:45 (v0.2 fix, native slot state sync): user reported that after switching with an extra key, pressing native 1 left him on page 2 slot 1 instead of page 1 slot 1. Root cause from the .org image: update 0x608730 branches on native actions 13/15/14/16, each doing `select(0xcbf680, action)` then `resolve(0xcbfa80, [mgr+0x218]=page, [mgr+0x21c]=slot, check)` and storing the result into `player+0x8054`. select only mutates manager state: it calls resolve(current page, action) and, if the result != 8 and slot != action, sets slot = action; otherwise it flips the page and probes slots 13/15/14/16 on the other page. The mod skipped select on purpose, so manager page/slot stayed at their old values while the weapon field was overwritten - the next native press then saw slot == action, took the paging branch and landed on the other page (exactly the reported symptom). Fix: ResolveHook locates the (page,slot) that natively resolves to the desired weapon (probes 2 pages x slots 13/15/14/16 through the trampoline, after the unlock check) and writes it into the manager; UpdateHook re-applies it after updateOriginal returns and logs "manager synced to page X slot Y" plus a done line with the resulting weapon and manager page/slot. If the weapon is absent from the native table the manager is left untouched. Rebuilt dist. Not verified in game yet.
